# 部署与安卓构建

## Linux 服务目录

部署脚本面向具备 systemd 的 x86_64 Linux，以 `/opt/fire-assistant` 为应用目录。服务器先安装 Docker Engine 和 Compose 插件；也可审核并运行 `deploy/install-runtime.sh` 准备运行环境。该脚本只处理应用目录及所需 Docker 服务，不处理其他应用。

```text
/opt/fire-assistant/
  shared/production.env     私有环境配置
  shared/uploads/           持久业务附件
  shared/downloads/         可选的 APK 下载文件
  backups/                  数据库与附件备份
  releases/<版本>/
    compose.yml             来自 deploy/compose.yml
    nginx.conf              来自 deploy/nginx.conf
    app.jar                 后端可执行 JAR
    web/                    dist/ 下的全部网页产物
  current                   当前成功发布的版本链接
```

每次发布使用新的版本目录。MySQL 使用固定 Compose 项目 `fire-assistant` 下的命名卷，不放入版本目录。

## 首次部署

1. 本地执行 `./scripts/Maven.ps1 package -DskipTests -B -ntp` 和 `npm run build`，得到后端 JAR 与 `dist/`。前端 `.env.production` 使用同源 `/api`。
2. 按上面的结构上传发布产物与两份配置，将后端 JAR 重命名为 `app.jar`。服务器需要开放网页端口，API 8081 仅绑定回环地址，数据库不对外开放。
3. 将 `deploy/production.env.example` 复制到服务器的 `shared/production.env`，填写独立随机数据库密码、root 密码及至少 32 字符的 JWT 密钥，限制配置文件读取权限。
4. 若为全新库、需要初始化四角色账号，首次明确设置 `DEMO_ENABLED=true`、`DEMO_PASSWORD=<至少六位的自定初始密码>`。初始化会同时创建示例单位和任务；当前没有仅创建管理员的独立向导。已有账号的库不会重新初始化。
5. 在服务器执行 `bash <源码或脚本目录>/deploy/activate.sh /opt/fire-assistant/releases/<版本>`。脚本检查 Compose 配置、等待数据库和 API 就绪、启动网页，健康后更新 current。
6. 初始化后将 `DEMO_ENABLED` 改为 `false`，在版本目录以该配置重建 API 容器；用管理员修改初始账号密码。数据库、账号和附件继续保留。

新库由 Flyway 建表；脚本不会自动导入任何私人数据库或上传目录。Nginx 示例监听 HTTP 80；使用 HTTPS 域名时，需要另行配置证书及 TLS 反向代理，再将 App 指向该域名。

## 升级与备份

1. 在服务器执行 `bash <脚本目录>/deploy/backup.sh`，同时备份数据库与 shared/uploads。
2. 将新产物上传到新的 releases 子目录，不覆盖 shared 或数据库卷。
3. 执行 activate.sh，检查网页及 `/api/health`。数据库结构变化由新增 Flyway 迁移处理。
4. 网页更新只需发布新网页；Android App 在线加载同一服务，返回前台时可检测网页新版本，并在没有未保存编辑时更新页面。原生能力、签名或目标站点变化需要重新构建 APK。

备份恢复应成对恢复 SQL 与附件，不把旧业务备份作为公开源码或首次部署的前置文件。回退网页可使用旧版本产物；数据库迁移的回退需要按具体迁移另行处理，不能仅换回旧 JAR。

## Android APK

构建需要 Node.js、Java 21、Android SDK Platform 36、Build Tools 36.0.0。当前脚本在 `.tools/java21/` 查找 JDK，在用户目录 `.cache/fire-assistant-build/android-sdk/` 查找 SDK，并使用同目录下的 Gradle 缓存。安卓构建工具与后端 Java 17 分开。

在项目根目录运行：

```powershell
./scripts/Build-Android.ps1 -ApiBaseUrl https://your-server.example/api
```

`your-server.example` 是占位域名，必须换成自己的服务。也可将 `VITE_API_BASE_URL=https://你的域名/api` 写入仅保存在本机的 `.env.android.local`，然后运行不带参数的构建脚本。显式参数优先；没有有效地址时脚本拒绝构建，公开配置不指向作者服务器。

脚本同步网页资产、设置 APP_WEB_URL、构建并验证签名，输出到 `releases/防消助手-<版本>.apk`。私钥和密码文件仅位于 `.runtime/android-signing/`，需要单独备份，后续更新继续使用同一签名。

直接使用 Gradle 或 Android Studio 时，需要先执行 `npm run android:sync`，然后设置 `APP_WEB_URL=https://你的域名/`，或给 Gradle 传入 `-PappWebUrl=https://你的域名/`。原生入口只允许该站点在内部导航；HTTP 放行域名由构建地址生成，HTTPS 使用系统信任证书。

安装后确认登录、图片上传与预览、PDF 分享、返回键及后台恢复。编译验证不能替代手机实测。
