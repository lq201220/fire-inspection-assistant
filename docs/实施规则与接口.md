# 架构与业务规则

## 技术结构

网页由 Vite 构建，使用 JavaScript 模块调用 Spring Boot JSON API。后端使用 Java 17、Spring Boot 3.5.16、JDBC、Spring Security 和 Flyway，数据存于 MySQL 8.4；Maven 负责构建和集成测试。

Android 工程以 WebView 加载构建时指定的服务站点，提供文件选择、返回键和附件分享。网页发布后 App 可加载新页面；原生功能或服务地址变化需要重新打包。

生产部署由 Nginx 提供网页并将 `/api/` 代理到后端。业务附件放在独立持久目录，通过鉴权接口读取，不公开映射上传目录。部署步骤见[部署与安卓构建](部署与安卓构建.md)。

## 角色与可见范围

| 角色 | 数据范围 | 办理职责 |
|---|---|---|
| ADMIN | 本机构全部任务、账号和单位 | 维护档案、创建分配、开始前调整、监管回看 |
| INSPECTOR | 分配给自己的任务，覆盖全部阶段 | 现场清单、问题及证据、退回补充、代录整改材料 |
| REVIEWER | 自己负责的待审核、整改中、已完成任务 | 审核问题与线索、退回、下达整改、无问题归档 |
| RECHECKER | 自己负责的整改中、已完成任务 | 代录材料、逐轮复查、闭环 |

检查员按分配办理，不领取开放任务；管理员不能替代审核员或复查员提交结论。相同权限范围适用于列表、详情、历史、单位关联记录与附件。退回检查后，审核员暂时看不到任务，重新送审后恢复。

## 状态与检查结论

正常流程：待检查 → 进行中 → 待审核 → 整改中 → 已完成。

无异常流程：待检查 → 进行中 → 待审核 → 已完成。退回补充：待审核 → 进行中 → 待审核。复查不合格保持整改中，收到新一轮材料再复查。

任务列表的“进行中”筛选是未逾期未完成任务的汇总，业务阶段仍单独保存；“已逾期”根据未完成任务的期限计算，不修改原始阶段或期限；已完成不再显示逾期。

清单状态为未检查、normal、abnormal、pending、na。提交时不得有未检查或 pending；na 必须有原因；abnormal 必须关联问题记录。异常结论与问题可以同事务保存，取消填写不产生半条记录。现场场所条件不再是提交前置；旧场所快照保留回看。

问题、总审核意见及未关联来源线索核验可以一次提交。任一问题退回则返回检查；已确认问题不被退回覆盖。复查缺当前轮材料时支持材料与复查一起提交，失败全部回滚；不合格之后必须补充新材料。

## 清单、风险与档案

管理员按单位类型和来源选择检查项目，至少下发一项；自定义项目在同机构、同单位类型中复用。单位类型包括学校、商业综合体、住宅小区、养老机构。项目、要求与依据在任务创建时形成快照，项目库或单位档案改动不覆盖既有任务。

单位风险等级和本次检查关注等级是人工选择的关注标签，不代表现场检查结果。历史画像根据现场结论及问题记录区分有异常、无异常；整改合格仍保留该次检查有异常的事实，仅展示已完成检查。

风险通过稳定 ID 关联任务与问题。一条来源线索关联一个主要问题，一个问题可关联多条线索；独立问题形成独立事项。审核排除未证实线索，复查合格关闭对应事项，不统一跳过未处理问题。

任务完成后只读。审核记录保存当时事实、意见、操作人与时间；材料和复查逐轮追加。单位详情三组关联数据默认折叠、每页五条、最近在前；任务内办理历史按时间从早到晚展示。

## 存储与一致性

业务表包括 sys_user、auth_session、supervised_unit、inspect_task、checklist_item、saved_checklist_item、removed_checklist_template、issue_record、risk_event、file_attachment、review_record、rectification_record、recheck_record、operate_log，另有 Flyway 迁移历史表。

关系键、机构、任务状态、版本、账号及附件元数据使用明确列及索引；表单扩展、数组、业务快照等使用 JSON 验证的 LONGTEXT。迁移位于 `backend/src/main/resources/db/migration/`，升级新增版本，不修改已执行 SQL。

任务写操作发送 `version`。后端锁定任务并检查版本、角色、机构与阶段，在事务中提交；过期版本返回 409，客户端保留输入并要求载入新数据。

会话有效期为八小时，退出即作废。账号停用、密码或角色变更会使旧会话失效。全新库仅在明确启用 DEMO_ENABLED 时初始化示例数据，已有账号不会重新初始化。

照片持久缓存于浏览器或 WebView 的 IndexedDB，按 API 来源、机构、账号和角色隔离，并按最新任务权限收敛。总上限 1 GiB，以最近使用时间淘汰；设备配额不足可提前回收或降级在线读取。退出、失效或主动清除会清理对应缓存。PDF 不持久缓存。

## API 约定

接口前缀 `/api`，除登录及健康接口外使用 `Authorization: Bearer JWT`。成功响应为 `{code:0,message:"成功",data:...}`，时间采用带偏移的 ISO 8601。

| HTTP 状态 | 含义 |
|---|---|
| 400 | 参数或业务前置条件不满足 |
| 401 | 未登录或会话失效 |
| 403 | 角色不允许 |
| 404 | 对象不存在或超出数据范围 |
| 409 | 版本或状态冲突 |
| 413 | 请求文件过大 |
| 500 | 未预期错误 |

具体请求字段见 [API 契约](API契约.md)。列表目前返回授权全量数据，前端执行筛选与分页；服务端任务与单位接口也提供搜索，不提供分页协议。
