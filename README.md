# 防消助手

消防监督检查管理系统，采用 Vite 前端、Spring Boot 后端和 MySQL 数据库，提供四角色任务分配、现场检查、问题审核、整改复查及历史档案。Android App 在线加载同一套网页。

## 本地启动

需要 Windows、PowerShell 7、Node.js 22.12+ 和正在运行的 Docker Desktop。在项目根目录执行：

```powershell
# 首次准备：生成本机配置，安装 Java 17 / Maven 3.9.9，启动 MySQL
./scripts/Setup.ps1
# 编译后端，不执行数据库集成测试
./scripts/Maven.ps1 package -DskipTests -B -ntp
npm run build
# 后台启动 API 与网页
./scripts/Start.ps1
# 停止项目，保留数据库和附件
./scripts/Stop.ps1
```

网页为 http://localhost:5173，健康接口为 http://localhost:8081/api/health。已有 Java/Maven 可使用 `Setup.ps1 -SkipDownloads`；配置存入不提交的 `.env`，首次生成后不会覆盖已有配置。

全新数据库且 `DEMO_ENABLED=true` 时会初始化四个账号及示例业务。初始密码由 `.env` 中的 `DEMO_PASSWORD` 指定；已有账号密码不会因修改该变量而重置。

## 办理流程

管理员创建账号和单位 → 创建任务并指定三类办理人员及检查项目 → 检查员逐项检查并登记异常 → 审核员统一审核 → 有问题进入整改复查，无问题审核归档 → 完成后查看历史画像和档案。

检查页不要求另填场所条件。异常结论与位置、事实、照片在同一问题表单保存；审核及缺材料时的复查也集中填写，提交一次列出缺项。历史画像按“全部 / 有异常 / 无异常”筛选已完成检查，整改合格仍保留原始异常事实。

页面每 5 秒后台同步，编辑、上传或隐藏页面时暂缓。照片按需加载并在设备持久缓存，按账号和权限隔离；总上限 1 GiB，满额淘汰最久未使用的图片。“我的 → 图片缓存 → 清除缓存”只删除本机副本。PDF 不持久缓存。

## 项目结构

```text
src/          网页界面、接口、后台同步与图片缓存
backend/      Java 服务、Flyway 迁移、业务清单模板与集成测试
android/      Android WebView 容器与 Gradle 工程
deploy/       Linux Docker Compose、Nginx、发布和备份脚本
scripts/      本地启动、构建、维护和浏览器回归脚本
docs/         使用、架构、接口、部署和开发文档
```

生产网页构建到 `dist/`，后端 JAR 位于 `backend/target/`。Android 构建必须指定自己的服务地址，详情见部署文档。

## 数据与本机文件

MySQL 使用命名卷，附件位于 `.runtime/uploads`；备份和恢复需要同时保存数据库与附件。日常启动不清空业务数据。

`.env`、`.env.*.local`、`.runtime/`、`.tools/`、签名、依赖、构建产物及测试报告均不提交。`DemoData.java` 和 `demo/seed.json` 还提供正式任务清单模板，应保留；Flyway 升级新增迁移，不修改已执行的 SQL。

`Reset-Demo.ps1` 是显式清库工具，`Cleanup-Uploads.ps1 -Apply` 会删除过期未绑定附件；均不属于日常启动或源码整理步骤。
